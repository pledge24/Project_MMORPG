# C++ 공통 컨벤션

클라이언트와 게임 서버의 C++ 코드 안의 규칙이다. 파일을 어디에 두고 무엇이라 부를지는 `docs/folder-structure.md`가 다룬다.
생성물(`*.pb.h`, `*PacketHandler.*`)과 생성물끼리의 `#include`는 생성기가 만들므로 손으로 고치지 않는다.

## 멤버 배치

`Server/ServerCore/`에는 `.cpp` 정의 순서만 적용한다.

- 헤더는 생성자·소멸자 → 엔진 인터페이스 오버라이드 → 기능 섹션 순서로 쓴다. 서버의 엔진 인터페이스는 기반 클래스의 `Init`·`Start`·`Tick`이다
- 기능 섹션 안에서는 public → protected → private 순서로, 함수 다음에 변수를 둔다
  — 접근 지정자로만 정렬하면 한 기능의 함수와 변수가 파일 양 끝으로 갈라진다
- 섹션 표시는 `//~ Begin <TypeName> Interface` / `//~ End <TypeName> Interface`와 `//~ <기능 이름>` 두 형태만 쓴다
- 클래스 안의 섹션 표시 바로 다음 줄에는 접근 지정자를 적는다. 앞 섹션과 같은 지정자여도 다시 적는다
  — 섹션 하나만 읽어도 접근 범위를 알 수 있고, 섹션을 옮겨도 접근 범위가 함께 옮겨진다
- 섹션은 기능마다 한 번만 연다. 여러 기능이 함께 쓰는 멤버는 마지막 섹션인 `//~ 공통`에 둔다. 기능이 하나뿐인 클래스는 섹션 표시를 생략한다
- `.cpp`는 헤더의 선언 순서대로 정의한다. 그 파일에서만 쓰는 자유 함수와 익명 네임스페이스는 첫 멤버 정의 위에 둔다
- 멤버 선언 순서를 바꾸면 초기화 순서를 확인한다. 초기화 리스트가 다른 멤버를 읽으면 읽는 값이 달라지고, 컴파일러가 경고하지 않을 때가 있다

## 주석

`Server/ServerCore/`와 `Server/GameServerTests/`에는 적용하지 않는다.

- 주석은 이름과 코드만으로 알 수 없는 것이 있을 때만 쓴다. 그 코드를 쓰는 쪽이 읽기 쉬운 것을 우선한다
- 헤더의 멤버 함수 주석은 쓰는 쪽이 언제 쓰고 무엇을 얻는지 알 수 있는 요약이다. 동작 방식은 `.cpp`에 적는다
  - 쓰는 쪽이 어기면 버그가 나는 제약은 남긴다. 검증하지 않는 입력, 실행 스레드, 잡아야 할 락, `nullptr` 허용 여부가 여기 해당한다
  - 반환값은 필요할 때 「실패하면 false」, 「없으면 nullptr」처럼 문장에 넣는다. `@param`·`@return` 태그는 쓰지 않는다
  - 내용은 2줄까지다. 1줄은 `/** 내용 */`로, 2줄은 여닫는 줄을 따로 둔 `/** */` 블록으로 쓴다
  — 2줄에 담기지 않는 내용은 대개 동작 설명이다
- 멤버 변수 주석은 이름으로 알 수 없는 것(담는 값, 단위, 범위)만 1줄로 적는다
- 클래스 주석은 반드시 쓴다. 첫 줄에 한 줄 요약을 쓰고, 빈 ` *` 줄 다음에 맡은 역할과 용도를 적는다. 빈 줄을 빼고 5줄까지다
  — 구현이 바뀌어도 고칠 필요가 없는 문장만 남긴다. 동작 과정, 채우는 시점, 의존 대상은 적지 않는다
- 동작이 없는 데이터 구조체는 요약 한 줄만 쓰거나 생략한다. 동작이 있는 구조체는 클래스 주석을 따른다
- `.cpp`에서는 생명주기와 흐름의 진입점(`Start`·`BeginPlay`, `Tick`, 입장 처리)에 그 블록이 흐름에서 맡는 일을 한 줄로 적는다. 예: `// 컴포넌트들 시작.`
- 그 밖의 `.cpp` 주석에는 코드만 봐서는 알 수 없는 이유와 함정을 적고, 지키지 않으면 무엇이 깨지는지까지 적는다
- 대상 코드가 없어진 주석과, 코드에 없는 대안을 택하지 않은 이유만 설명하는 주석은 지운다

```cpp
/**
 * 플레이어가 가진 아이템의 보관소.
 *
 * 아이템을 종류별 슬롯에 보관하고, 아이템을 넣고 빼는 창구가 된다.
 */
class InventoryComponent : public EntityComponent
{
public:
    /**
     * 클라이언트가 보낸 슬롯에서 count개를 빼고, 바뀐 슬롯을 outSlot에 쓴다(nullptr 불가).
     * 슬롯이 잘못됐거나 수량이 모자라면 아무것도 바꾸지 않고 false.
     */
    bool RemoveItem(const Protocol::Slot& requestSlot, OUT Protocol::Slot* outSlot, int32 count = 1);
```
