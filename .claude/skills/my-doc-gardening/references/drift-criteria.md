# 드리프트 축 판정 기준

문서의 **주장**이 지금의 코드, 환경, GitHub 상태와 맞는지 본다. 주장은 실행해 보거나 찾아보면 참·거짓이
갈리는 문장이다. 「경로 X에 있다」, 「스위트는 N개다」, 「아직 없다」가 주장이다. 「왜 이렇게 했는가」는
주장이 아니라 근거라서 이 축이 보지 않는다.

## 일하는 방식

1. 대상 문서마다 주장을 뽑는다. 기준이 있으면 diff가 건드린 경로, 심볼, 숫자와 닿는 주장부터 뽑는다
2. 주장마다 아래 표의 방법으로 확인한다. 확인은 반드시 명령이나 파일 읽기로 한다. 기억으로 판정하지 않는다
3. 틀린 주장만 발견으로 올린다. 맞는 주장은 적지 않는다

완료 기준: 대상 문서의 주장마다 확인했거나, 확인하지 못한 이유가 있다. 확인하지 못한 주장은 개수와 대표
예시 하나를 리포트 끝에 「확인하지 못한 것」으로 적는다.

## 규칙

| ID | 주장의 종류 | 확인 방법 |
|---|---|---|
| D1 | 경로, 폴더 트리, 파일 목록 | `git ls-files`로 실재를 본다. 기계 검사(`path-ref`)는 백틱 안에서 최상위 폴더로 시작하는 경로만 본다. 백틱 없는 경로, 모듈 기준 상대 경로(`P1/Network`), 확장자 없는 폴더, 목록에서 빠진 파일은 이 축이 본다 |
| D2 | 명령, 스크립트 인자, npm 스크립트, CI 단계, `.env` 키 | 스크립트의 `param` 블록, `package.json`의 `scripts`, `.github/workflows/*.yml`, 설정을 읽는 코드를 읽는다 |
| D3 | 클래스, 함수, 상수, 모듈, 로그 카테고리 이름 | 이름을 저장소에서 찾는다. 없으면 `git log -S<이름> --oneline`으로 언제 바뀌거나 사라졌는지 찾아 근거에 적는다 |
| D4 | 개수와 목록(「둘뿐」, 「N개」, 표의 행) | 실제로 센다. 센 명령을 근거에 적는다 |
| D5 | 상태(「없다」, 「아직」, 「미착수」, 「이후 변경 없음」) | 지금 상태를 확인한다. 「이후 변경 없음」류는 그 문서의 마지막 수정 이후 관련 경로의 `git log`를 본다 |
| D6 | 포트, 주소, DB 인스턴스, 환경 변수 이름 | 설정을 읽는 코드(`ServerConfig`, 설정 클래스, `configs.js`)를 읽는다 |
| D7 | 두 문서가 같은 사실을 다르게 적은 것 | 코드로 어느 쪽이 맞는지 판정한다. 틀린 쪽에 수정안을 낸다. 코드로 갈리지 않으면 판단 필요다 |
| D8 | 참조가 가리키는 내용 | 참조 대상이 있는지와, 그 대상이 주장한 내용을 담는지 본다. 기계 검사가 안 보는 것을 맡는다. 문서 이름 없이 쓴 「절」 참조, 번호는 있지만 지금은 다른 항목인 backlog 참조, ADR과 work 파일 안의 참조 |
| D9 | work 파일 진행 표의 상태와 PR 열 | `gh pr view <N> --json state,mergedAt,baseRefName`과 `gh issue view <N> --json state`로 본다. 머지된 PR인데 「진행」이나 「대기」면 확정이다. `gh`는 조회만 한다 |
| D10 | 자리표시자(`XX`, `TODO`, `미정`, 빈 칸) | 문서에 남은 자리표시자를 찾고, 채울 값을 코드나 `git log`에서 찾을 수 있으면 수정안으로 낸다 |

## 드리프트로 올리지 않는 것

- **`docs/folder-structure.md`의 목표 상태.** 그 문서는 목표를 적고, 코드와 다르면 문서가 맞다고 스스로
  정한다(머리말). 코드가 다르면 문서를 고치는 수정안 대신 판단 필요로 올리고 「코드 쪽 부채 후보」라고 적는다
- **코드 블록 안의 예시 이름.** `docs/conventions.md`처럼 규칙을 보이려고 지어낸 이름은 코드에 없어도 된다
- **work 파일의 「기록」과 날짜가 붙은 실측.** 「2026년 9월 17일 실측」은 그날의 기록이다. 다만 그 실측이
  지금의 동작처럼 읽히는 문장에 쓰였으면 판단 필요로 올린다
- **`docs/references/`.** 현행 제약이 아니다

## ADR

ADR은 결정 당시의 서술을 보존하고, 날짜를 적은 덧붙임으로만 갱신한다(`ADR-0007` 「2026년 9월 22일 덧붙임」의
설명). 그래서 ADR의 낡은 주장도 똑같이 확인하되, 수정안은 본문 문장을 바꾸지 않고 덧붙임 문단으로 쓴다.

```
**YYYY년 M월 D일 덧붙임 — <요지 한 문장>.** <무엇이 바뀌었고 지금은 어떤지. 근거가 된 커밋이나 문서>
```

덧붙임이 이미 그 변화를 다뤘으면 발견으로 올리지 않는다.
