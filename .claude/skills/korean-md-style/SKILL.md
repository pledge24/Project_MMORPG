# 한국어 마크다운 문서 판단 기준
 
한국어 md 파일이 Claude Code와 한국 개발자 양쪽에 읽히도록 문장과 표현을 판단하는 기준이다.
파일 종류를 가리지 않는다.
 
**다루는 것**: 어떻게 쓰는가. 문체, 문장, 표현, 표기.
**다루지 않는 것**
- 무엇을 쓰는가. 내용의 사실 여부, 최신성, 정보의 누락 여부
- 문서의 구성, 목차, 절 순서
— 구성이 필요한 문서에는 이미 템플릿이 있다. 템플릿이 있으면 템플릿을 따르고, 이 스킬은 그 안에 들어가는 문장만 판단한다. 내용이나 구성에 문제가 보이면 고치지 않고 질문으로 올린다.

## 두 가지 모드
 
| 상황 | 모드 |
| --- | --- |
| 문서를 새로 쓰거나 기존 문서를 고친다 | 작성 모드 |
| 문서가 올바른 방식으로 쓰였는지 확인한다 | 진단 모드 |
| 둘 다 요구된다 | 진단 → 승인 → 수정 순서로 한다 |

---
 
## 작성 모드

### 1. 초안을 쓴다

이 단계에서는 문체 규칙을 신경 쓰지 않는다. 내용을 다 꺼내는 것이 목적이다.
템플릿이 있으면 템플릿의 절 구성을 그대로 쓴다. 구성을 새로 제안하지 않는다.

### 2. 규칙을 적용한다

`references/style-rules.md`를 읽고 아래 순서로 훑는다. 순서를 지킨다.
— 표기부터 고치면 뒤에 문장 구조가 바뀌면서 고친 것이 날아간다.

1. 2절 — 간결성 (문장이 나뉘거나 통째로 사라진다)
2. 3절 — 번역투 (문장이 통째로 바뀐다)
3. 4절 — 주체와 구체성
4. 1절 — 문체와 어미
5. 5~7절 — 일관성, 표기, 기호

### 3. 체크리스트를 통과시킨다

`references/style-rules.md` 8절의 체크리스트를 항목별로 확인한다. 통과하지 못한 항목은 고치거나, 고치지 않는 이유를 사용자에게 말한다.

## 진단 모드

### 1. 대상을 확정한다

검사할 파일 목록을 먼저 정해 사용자에게 보여준다.

### 2. 위반을 수집한다

`references/style-rules.md`를 읽고 파일별로 위반을 모은다. 각 위반에 아래 다섯 가지를 기록한다.

1. 파일 경로와 줄 번호
2. 규칙 번호
3. 원문
4. 수정안
5. 심각도

**규칙을 어겼는지 애매하면 위반으로 올리지 않는다.**
— 애매한 것까지 올리면 리포트가 길어져 진짜 문제가 묻힌다. 대신 리포트 맨 아래 「판단이 필요한 것」에 질문으로 남긴다.

### 3. 심각도를 매긴다

| 심각도 | 기준 | 해당 규칙 |
| --- | --- | --- |
| 높음 | 지시가 모호해지거나 뜻이 달라진다 | 4절 전체, 1.2 |
| 중간 | 읽기 어려워진다 | 1절 나머지, 2절, 3절, 5절 |
| 낮음 | 표기가 어긋난다 | 6절, 7절 |

### 4. 리포트를 낸다

아래 형식을 그대로 쓴다.

```markdown
## 진단 결과

대상: <파일 수>개 파일 · 위반 <총 건수>건 (높음 N · 중간 N · 낮음 N)

| # | 파일 | 줄 | 심각도 | 규칙 | 문제 |
| --- | --- | --- | --- | --- | --- |
| 1 | CLAUDE.md | 41 | 높음 | 4.3 | 조건이 "적절히"로만 적혀 있다 |

### 1 · CLAUDE.md 41행 · 높음 · 규칙 4.3

원문:
> 테스트 파일이 너무 길어지면 적절히 나눈다.

수정안:
> 테스트 파일이 200줄을 넘으면 파일을 나눈다.

근거: 판단 기준이 없으면 에이전트가 매번 다르게 해석한다. 200줄은 예시 수치이므로 실제 기준을 알려주면 반영한다.

## 판단이 필요한 것

- README 12행의 "배포 절차"가 실제 절차와 다른지 확인이 필요하다. 내용은 이 스킬의 범위 밖이라 고치지 않았다.
```

### 5. 승인을 받는다

**승인 없이 파일을 고치지 않는다.**
— 문체 수정은 되돌리기 쉬워 보이지만, 여러 파일에 한꺼번에 적용하면 어디가 바뀌었는지 추적하기 어렵다.

번호로 고를 수 있게 묻는다. 예: "1~4번, 7번을 적용할까?" 또는 "높음만 적용할까?"

### 6. 승인된 것만 고친다

- 승인된 번호 외의 것은 손대지 않는다
- 수정안에 적힌 그대로 고친다. 고치는 중에 더 나은 표현이 떠올라도 리포트에 없던 변경을 넣지 않는다
- 문장을 지워 정보가 사라지는 수정은 하지 않는다. 정보는 유지한 채 표현만 바꾼다
- 절을 추가하거나 순서를 바꾸지 않는다

### 7. 결과를 보고한다

고친 파일과 항목 번호를 나열한다. 적용하지 않은 항목이 있으면 이유를 한 줄로 적는다.

## 자주 걸리는 열 가지

`references/style-rules.md`를 열기 전에 이것부터 확인한다. 실제 문서에서 이 열 가지가 위반의 대부분을 차지한다.

| # | 규칙 | 나쁜 예 | 좋은 예 |
| --- | --- | --- | --- |
| 1 | 4.2 모호한 말을 안 쓴다 | 너무 길어지면 적절히 나눈다 | 200줄을 넘으면 나눈다 |
| 2 | 4.1 주체를 분명히 한다 | 산출물이 생성되어집니다 | 빌드 스크립트가 산출물을 만든다 |
| 3 | 2.1 한 문장에 하나만 담는다 | 인증을 마치면 토큰이 발급되고, 이 토큰은 1시간 뒤 만료되므로 갱신이 필요하다 | 인증을 마치면 토큰이 발급된다. 토큰은 1시간 뒤 만료되므로 갱신한다. |
| 4 | 3.2 껍데기 한자어를 뺀다 | 삭제 작업을 수행한다 | 삭제한다 |
| 5 | 3.3 `~을 통해`를 안 쓴다 | 이 API를 통해 가져온다 | 이 API로 가져온다 |
| 6 | 3.1 명사 나열을 동사로 되돌린다 | 인증 처리가 완료된 후 접속 설정 진행이 가능하다 | 인증한 뒤 접속하도록 설정한다 |
| 7 | 2.3 메타 담화를 지운다 | 앞서 설명했듯이, 아시겠지만 | (삭제) |
| 8 | 1.2 어미를 섞지 않는다 | 한 문서에 `~합니다`와 `~한다`가 섞임 | 전부 `~한다` |
| 9 | 4.6 지시어에 대상을 붙인다 | 아래가 다 나올 때까지 | 아래 다섯 가지가 다 나올 때까지 |
| 10 | 6.2 라틴 문자 뒤 조사를 붙여 쓴다 | Phase 를, ADR 을 | Phase를, ADR을 |
