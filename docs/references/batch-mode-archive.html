00한 줄 요약

사람 없이 step들을 순차 실행하는 헤드리스 배치 모드. 웹 잔재가 아니라 언리얼 전용으로 정교하게 재작성된 물건이며, 설계 품질은 높다. 하지만 지금 들이면 하네스가 두 개의 실행 모드·두 개의 커밋 체제·두 개의 빌드 경로를 갖게 된다. 하네스 복잡도 상한 초과로 보류. 즉시 가치가 있는 설계 4건은 현행 하네스에 이미 편입했다(§05 — 해동 시 중복 도입 금지).

01이 물건의 정체

두 파일은 한 세트다. harness.md는 사람과 함께 작업을 step 파일들로 설계하는 워크플로우 문서, execute.py는 그 step들을 사람 없이 순차 실행하는 executor다.

사람+세션
A~D 단계 (대화형, 사람 게이트 있음) — 탐색 → 논의(C++/BP 경계 합의) → step 설계(scope 최소화, 자기완결, 시그니처 수준 지시) → phases/{task}/step{N}.md + index.json 생성
executor
feat-{task} 브랜치 checkout → CLAUDE.md + docs/*.md 전문을 가드레일로 프롬프트에 주입 → 완료된 step의 summary 누적 전달
Claude -p
claude -p --dangerously-skip-permissions 헤드리스 세션이 step 하나를 수행하고 index.json에 completed / error / blocked 자기신고
executor
자기신고 불신 — step 파일의 AC 코드블록에서 커맨드를 파싱해 직접 재실행, exit code로만 최종 판정 (AC 타임아웃 60분)
executor
실패 시: Source/ Config/를 git checkout+clean으로 롤백 → 실패 로그 끝 6,000자를 프롬프트에 되먹여 재시도 (최대 3회)
executor
성공 시: 경로 화이트리스트 커밋 — 코드는 feat, phases 메타데이터는 chore로 분리. 커밋은 executor 전담, 세션은 커밋 금지
사람
blocked = 정상 인계 — 에디터 작업(BP 노드, 에셋, 레벨, ini)이 필요하면 blocked_reason(무엇을/어디서)을 남기고 중단. 사람이 처리 후 pending으로 되돌려 재개

기타: --no-vcs(Perforce용, git 조작 전체 생략 — 단 롤백도 사라짐), --push(완료 후 브랜치 push), step별 stdout/stderr을 step{N}-output.json으로 보존.

02왜 지금 들이지 않나

제1 근거는 복잡도 상한이다. 하네스는 이미 신경 쓸 것이 많고, 이 모드를 들이면 실행 모드 2개(대화형/배치), 커밋 체제 2개(세션 커밋/executor 커밋), 빌드 경로 2개(Rider MCP/CLI)를 동시에 유지해야 한다. 1인 프로젝트에서 유지비가 편익을 앞선다. 급하지도 않다 — 아래 충돌 3건이 보여주듯 전제 조건이 아직 하나도 성립하지 않았다.

충돌내용해동 시 처리
빌드 경로 executor의 AC는 파이썬 subprocess라 Rider MCP 호출 불가. AC가 shell 커맨드여야 하므로 CLI 빌드 경로(UBT/Build.bat, MSBuild) 재개방이 필수 — "Rider MCP 전용" 결정과 정면충돌 "CI 필요 시 재검토" 단서의 성립을 그때 판정. execute.py는 기능적으로 미니 CI(자동 빌드·판정·롤백)라는 해석과, 단서의 CI는 외부 CI(GitHub Actions류)를 뜻했다는 해석이 갈림 — 해동 시점에 사용자가 확정
사람 게이트 step 실행 중 사람 게이트 없음. 단 게이트가 사라진 게 아니라 상류(C~D 단계 step 설계·승인)로 이동한 구조. AC 기계 판정은 P-G-E Evaluator의 결정론적 버전이라 원칙과 모순은 아님 grilling을 C~D 단계에 꽂아 step 파일을 심문한 뒤 배치 실행. AC가 못 잡는 것(설계 일관성·명명·아키텍처 이탈)은 phase 종료 후 code-reviewer로 보완
커밋 체제 현행: 세션이 커밋(git commit -F 규칙 정비됨). 이 모드: 세션 커밋 금지 + executor 커밋. executor가 CLAUDE.md 전문을 주입하므로 한 프롬프트 안에서 두 규칙이 충돌 CLAUDE.md 커밋 절에 "배치 모드에서는 executor가 커밋을 관리하며 세션은 커밋하지 않는다" 조건 분기 한 줄 추가

보안 메모: --dangerously-skip-permissions는 권한 프롬프트만 건너뛰고 PreToolUse 훅(block_dangerous.py)은 그대로 돈다. 단 ue_execute_python 구멍은 대화형에서 "보고 규칙+사람의 눈"이 방어인데 헤드리스에서는 눈이 빠짐 — 배치 채택 시 이 구멍의 위험도가 한 단계 오른다.

03해동 조건

시점: UE 클라이언트 신규 기능 국면 진입 시 (판정표 #03 Unreal MCP 도입과 같은 시기). 근거: CODE_PATHS = ["Source", "Config"]라 서버는 커밋 대상조차 아니고, harness.md의 어휘 전체(UCLASS, Build.cs, GAS, 에디터 blocked)가 클라 전용. MMORPG 클라의 반복 구현 물량(어빌리티·어트리뷰트·서브시스템 계열)이 배치가 값어치를 하는 지형이다.

해동 전 체크리스트 — 전부 충족 후 재판정

04해동 시 사용법

실행 커맨드

python3 scripts/execute.py {task-name}           # 순차 실행
python3 scripts/execute.py {task-name} --push    # 완료 후 push
python3 scripts/execute.py {task-name} --no-vcs  # Perforce (롤백 없음 주의)

준비 순서

  1. 대화형 세션에서 harness.md A~D를 수행한다. 특히 C 단계에서 C++/BP 경계 합의(자동화 가능 범위의 경계), step당 한 클래스 계열 원칙, 에디터 작업 지점의 blocked 사전 설계를 지킨다. grilling 채택 상태라면 여기서 step 파일들을 심문한다.
  2. AC는 실행 가능한 shell 커맨드로만 적는다. ## Acceptance Criteria 제목 바로 아래 첫 코드블록에서 파싱되며, 커맨드 원문은 CLAUDE.md 명령어 절에서 그대로 복사한다. AC 사다리 1~3단만 넣는다(4단 인게임 검증은 phase 종료 후 사람이).
  3. phases/index.json과 phases/{task}/index.json을 D-1·D-2 스키마대로 생성한다. status는 전부 "pending", 타임스탬프는 넣지 않는다(executor가 기록).
  4. 워킹 트리를 깨끗이 하고 실행한다. executor가 브랜치를 checkout하므로 미커밋 변경이 있으면 실패한다.

에러 복구

  • error 3회 재시도 후 실패. index.json에서 해당 step status를 "pending"으로 되돌리고 error_message를 지운 뒤 재실행. 원인 분석에는 step{N}-output.json과 되먹임 로그를 본다.
  • blocked 실패 아님. blocked_reason의 작업을 에디터에서 처리하고 "pending"으로 되돌린 뒤 재실행.

한계 (설계상 의도된 것)

  • AC가 잡는 것은 컴파일·테스트 통과뿐이다. 설계 일관성·명명·아키텍처 이탈은 phase 종료 후 리뷰(code-reviewer)로 잡는다.
  • diff를 실시간으로 보지 못한다. 이탈 발견이 step 단위로 늦어지는 것을 감수하는 대신 물량 처리 속도를 얻는 트레이드오프다.
  • --no-vcs에서는 재시도 전 롤백이 사라져 이전 시도의 잔여 파일이 다음 시도를 오염시킬 수 있다.

05이미 수확한 것 — 해동 시 중복 도입 금지

아래 4건은 배치 모드와 무관하게 가치가 있어 판정 시점에 현행 하네스로 편입했다. 해동할 때 이것들을 "이 모드의 기능"으로 다시 들이지 말 것.

✓
자기신고 불신 원칙 — 완료 선언 전 검증 커맨드 실제 실행을 CLAUDE.md 검증 절에 원칙으로 등재. 세션 1 미완 항목("빌드 초록 최종 확인")이 이 원칙의 첫 사례.
✓
blocked = 정상 인계 — plans 체크리스트에 [B] blocked — 무엇을/어디서 상태 도입. 세션에게 "에디터 작업은 우회하지 말고 blocked로 기록 후 중단" 지시.
✓
summary 한 줄 누적 — plans 완료 항목 옆에 "생성 파일 경로 + 핵심 결정" 한 줄. 다음 세션 프롬프트는 이 줄들을 긁어모아 작성.
✓
AC 사다리 + step 설계 원칙 6종 — 계획 파일과 세션 프롬프트 작성 지침으로 채택 (scope 최소화 / 자기완결성 / 사전 준비 강제 / 시그니처 수준 지시 / "X 하지 마라. 이유: Y" / 에디터 작업은 step이 아니라 종료 조건).

06원본 위치

원본 파일은 harness_framework 레포에 보존한다: commands/harness.md, scripts/execute.py. 이 문서와 원본 2개가 해동에 필요한 전부다. 해동 재판정 시 이 문서의 §02 충돌 표와 §03 체크리스트에서 시작하면 판정 경위를 복원할 필요가 없다.
