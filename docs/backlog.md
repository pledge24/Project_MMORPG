## 4. CI — 게임 서버와 UE 클라 티어

인증 서버 티어는 `.github/workflows/ci.yml`에 들어갔다. 남은 두 티어는 **호스티드 러너에서
돌지 않는다.**

**무엇이 막는가** (2026년 9월 17일 실측)

| 티어 | 막는 것 |
| --- | --- |
| 게임 서버 | `.vcxproj`의 `PlatformToolset`이 `v145`다. GitHub `windows-2025` 러너의 Visual Studio는 2022(17.14)이고 툴셋은 `v143`까지다 |
| UE 클라 | UE 5.8 런처 설치본이 필요하다. 러너에 엔진이 없다 |

**선행 조건**: 아래 두 방향 중 하나를 사람이 정한다.

1. **self-hosted 러너를 이 머신에 등록한다.** 두 티어가 함께 풀리는 유일한 방법이다.
   **다만 이 저장소는 공개다.** 포크에서 온 PR이 이 머신에서 코드를 실행하게 되므로,
   워크플로 트리거를 어디까지 열지부터 정해야 한다. 머신이 켜져 있어야 한다는 제약도 있다.
2. **게임 서버만 호스티드로 옮긴다.** `PlatformToolset`을 `v143`으로 내린다. 로컬 개발 환경이
   VS 18이므로 `docs/build.md`의 빌드 경로와 함께 판단한다. **UE 클라는 이 방법으로 풀리지
   않는다.**

**완료 신호**: 푸시나 PR에서 세 티어가 자동으로 돌고 실패 시 빨간 체크가 뜬다.

## 5. UE L2 Automation Test

**왜 지금**: L1(LLT)은 폐기됐지만 L2는 별도 타깃이 필요 없어 설치본에서 바로 된다
(`IMPLEMENT_SIMPLE_AUTOMATION_TEST`가 설치본 `Core/Public/Misc/AutomationTest.h:4297`에 존재).

**선행 조건**: 없다. 사람 손이 필요하다고 적어 두었던 제약이 풀렸다.

**실행 경로가 실측으로 확인됐다.** `P1/Scripts/Run-UeTests.ps1`이 `UnrealEditor-Cmd`로
에디터를 띄우지 않고 돌린다. 리포트의 `index.json`을 읽어 판정하고 스스로 종료 코드를
낸다. 벽시계 시간은 14.5초와 47.3초로 측정했다. 떠 있는 에디터와 충돌하지 않는다.

**종료 코드만 보면 안 된다.** `UnrealEditor-Cmd`는 매칭된 테스트가 하나도 없어도 `0`을
돌려준다. 필터 오타가 그대로 초록으로 보인다. 위 스크립트가 이 구멍을 막는다.

착수 단계: `P1/Source/P1/Tests/`에 테스트 1개 → `Build.bat`으로 에디터 타깃 빌드
(`docs/build.md` 「빌드 명령」, **에디터를 닫고 돌린다**) → `Run-UeTests.ps1`.

첫 테스트는 빨강으로 먼저 쓴다. 테스트가 실제로 실패할 때 `failed` 필드가 올라가는지
아직 재지 못했고, 그 자리에서 함께 측정된다.

대체 실행 경로 둘은 남겨 둔다. 에디터가 이미 떠 있을 때 프로세스 시작 비용을 치르지 않는
언리얼 MCP의 `RunTests`와, 사람이 쓰는 에디터의 `Window > Test Automation`이다.

첫 대상 후보는 이동 보간 수식(`AP1Creature`의 `MoveQueue`) 정도다. 클라 쪽에 남은 순수 로직이
얇다는 점도 함께 고려한다.

**완료 신호**: `Run-UeTests.ps1`이 이 저장소의 테스트 1개에 종료 코드 `0`을 낸다.

## 6. 장착 슬롯과 퀵 슬롯의 매핑 대상 결정

**왜 지금**: `SLOT_TYPE_EQUIPPED`와 `SLOT_TYPE_QUICK`은 프로토콜에 정의돼 있으나 인벤토리의
`slotTypeToItemTypeMappings`에는 없다. #25가 이 둘을 크래시 없는 거부로 고정했고, #27이
의도적 제외로 `InventoryTests.cpp`의 기대 집합에 못박았다. 지금 남은 것은 **둘을 어떤 아이템
타입에 매핑해야 옳은지를 정하는 설계 판단 하나**뿐이라 범위가 선명하다.

**선행 조건**: 장착 슬롯을 `EquippedGear`가 계속 단독으로 관리할지 정한다. 퀵 슬롯은 서버에
저장소 자체가 없으므로 무엇을 어디에 저장할지부터 정한다. 1번과 같은 파일을 건드리므로 두
작업을 묶으면 파일을 두 번 열지 않는다.

**완료 신호**: 두 슬롯 타입이 매핑 표에 들어가거나, 넣지 않는 이유가 `docs/ARCHITECTURE.md`에
적힌다. 어느 쪽이든 `InventoryTests.cpp`의 기대 집합을 함께 갱신해 테스트가 초록으로 남는다.
