# Tech Debt

지금 틀린 것만 담는다. 해결이 확정되면 항목을 지운다 — 수정 완료 표기를 남기지 않는다.
무엇을 어떻게 고쳤는지는 커밋이 갖는다.

항목 15개 (높음 0 · 중간 2 · 낮음 13) · 다음 번호 TD-088

## 작성 방법

항목마다 `TD-NNN` 번호를 붙인다. 번호는 항목을 만든 순서다. 새 항목에는 파일 맨 위의 「다음 번호」를 쓰고,
「다음 번호」를 하나 올린다. 항목을 지워도 그 번호를 다시 쓰지 않는다. 다른 문서에서 항목을 가리킬 때는 번호와
제목을 함께 적는다.

항목은 심각도 절(`# 높음`, `# 중간`, `# 낮음`)에 넣는다. 세 절은 `---`로 나누고, 항목이 없는 절도 지우지 않는다.
심각도를 바꾸면 항목을 그 절로 옮기고 번호는 그대로 둔다. 한 절 안에서는 난이도가 낮은 항목을 위에 두고,
난이도가 같으면 번호 순서로 둔다.

### 새 항목 양식

아래 블록을 복사해서 쓴다.

```markdown
## TD-NNN 무엇이 틀렸는가를 한 줄로
> **심각도:** 높음 · **난이도:** 중간 · **범위:** 기능 · client
> 위치: `경로` N~N줄
> 등록일: 2026년 0월 0일

문제 상황을 적는다. 필요하면 표를 쓴다.

### 영향

**문제 유형** · **문제 유형** — 방치했을 때의 손실과 리스크를 실측 결과로 적는다.
```

- 줄 번호는 특정할 수 있을 때만 적는다. 파일 전체가 문제면 괄호에 총 줄 수를 적는다
- 경로가 넷을 넘거나 특정할 수 없으면 공통 상위 디렉터리를 적는다
- 영역은 하나만 고른다. 나머지는 본문에서 언급한다
- 문제 유형은 최대 두 개까지 적는다
- 항목을 추가하거나 지우면 파일 맨 위의 개수 줄을 함께 고친다. 추가할 때는 「다음 번호」도 고친다
- 항목을 고칠 GitHub 이슈에는 `tech-debt` 라벨을 붙인다. 이슈를 먼저 열고 나중에 항목을 적었으면 그때 붙인다

|---|---|---|

### 범위

부채가 영향을 미치는 코드의 범위다.

| 프로젝트 | 프로젝트 전반의 구조나 여러 기능에 영향을 준다 |

## TD-085 다른 워크트리의 에디터가 떠 있으면 클라이언트 빌드 스크립트를 쓸 수 없다
> **심각도:** 중간 · **난이도:** 낮음 · **범위:** 파일 · build
> 위치: `P1/Scripts/Invoke-UeBuild.ps1` (에디터 확인)
> 등록일: 2026년 10월 29일

빌드 스크립트는 명령줄에 `P1.uproject`라는 파일 이름이 든 에디터를 모두 이 프로젝트의 에디터로 본다. 워크트리마다 `P1.uproject`가 있으므로
다른 워크트리에서 띄운 에디터도 걸린다. 스위치 없이는 1로 끝나고, `-CloseEditor`를 붙이면 그 에디터까지 닫는다.

스크립트를 거치지 않아도 UBT가 막는다. UBT는 Live Coding 세션을 엔진 실행 파일 경로로 만든 뮤텍스(`Global\LiveCoding_<UnrealEditor.exe 경로>`)로 찾는데,
에디터 타깃의 실행 파일은 엔진의 `UnrealEditor.exe` 하나라 다른 워크트리의 에디터가 Live Coding을 켜 두면 「Unable to build while Live Coding is active」로 실패한다.
#341은 `Build.bat`을 직접 부르고 `-NoHotReloadFromIDE`로 이 검사를 건너뛰어 빌드했다. 이 워크트리의 DLL은 다른 에디터가 잡고 있지 않아 빌드는 성공했다.

### 영향

**작업 흐름 정지** · **데이터 손실 위험** — 두 세션이 워크트리를 나눠 병렬로 진행하면 한쪽 에디터가 떠 있는 동안 다른 쪽은 문서의 빌드 명령으로 빌드할 수 없다.
`-CloseEditor`를 붙이면 다른 세션의 저장하지 않은 에셋 변경이 사라진다.

## TD-083 벽 통과로 거절된 클라이언트는 서버 위치로 돌아오지 않아 이동이 계속 거절된다
> **심각도:** 중간 · **난이도:** 중간 · **범위:** 기능 · server, client
> 위치: `Server/GameServer/Game/Room/Room.cpp` `Room::C_HandleMove`, `Server/GameServer/Game/Room/MoveValidation.cpp`
> 등록일: 2026년 10월 29일

서버는 거절한 이동을 버리기만 하고 보낸 클라이언트에 알리지 않는다(`docs/ARCHITECTURE.md`의 이동 판정 불변식). 속도로 거절된 이동은
경과 시간이 쌓이면 다시 받아들여진다. 벽 통과로 거절된 이동은 다르다. 서버의 위치는 벽 이쪽에 남고 클라이언트는 벽 저쪽에 있으므로,
다음 이동도 같은 벽을 지나 계속 거절된다. 다른 플레이어에게는 그 자리에 멈춘 모습으로 보이고, 그 위치로 저장된다.
#338 이슈 본문은 「거절하면 지금처럼 서버 위치로 보정한다」고 적었지만 지금 서버에는 그 보정이 없다. 코드를 읽고 판단했고 재현하지 않았다.

같은 이유로, 표면 이동이 지나는 폴리곤이 64개(`NavQuery`의 `MAX_SURFACE_VISITS`)를 넘는 긴 이동은 중간에서 멈춰 벽 통과로 거절될 수 있다.
경과 시간에 상한이 없어 오래 서 있다가 보낸 첫 이동이 길 수 있다. 지금 맵은 폴리곤이 크고 적어(259개) 0.2초 이동이 넘을 일은 없다.

### 영향

**버그 발생 가능성 증가** — 클라이언트의 충돌과 서버의 navmesh가 어긋난 자리(복셀 오차, 추출에서 빠진 충돌)를 지난 플레이어는
서버에서 움직이지 못한다. 다시 접속하면 서버 위치로 돌아온다.

## TD-063 훅의 SQL 스키마 변경 판정이 문자열 리터럴 안의 낱말에도 걸린다
> **심각도:** 낮음 · **난이도:** 낮음 · **범위:** 함수 · build
> 위치: `.claude/hooks/guard_dangerous_cmd.py` (`check`, `SQL_DDL_PATTERNS`)
> 등록일: 2026년 10월 21일

`check`는 WHERE 판정 전에만 `_strip_sql_noise`로 주석과 문자열 리터럴을 지운다. `SQL_DDL_PATTERNS`는 원문에 그대로
적용하므로, 문자열 안의 `CREATE TABLE`도 스키마 변경으로 판정한다. `claude_rw`의 권한을 확인하면서 찾았다.
`HAS_PERMS_BY_NAME(NULL, 'DATABASE', 'CREATE TABLE')`를 조회하는 `SELECT`가 「CREATE TABLE/DATABASE」로 막혔다
(2026년 10월 21일 실측). 권한 이름을 인자로 넘기지 않는 `fn_my_permissions`로 바꿔 조회했다.

### 영향

**변경 비용 증가** — 조회만 하는 문장이 막혀 다른 쿼리로 돌아가야 한다. 차단 쪽으로 틀리므로 위험한 문장이 새지는 않는다.

## TD-065 아이템 요청이 중간에 실패하면 바뀐 칸이 남아 다음 응답에 실린다
> **심각도:** 낮음 · **난이도:** 낮음 · **범위:** 기능 · server
> 위치: `Server/GameServer/Game/Entities/Player.cpp` 275줄 이후 (`ProcessEquipGear`, `ProcessUnequipGear`)
> 등록일: 2026년 10월 21일

칸 배열은 바뀐 칸을 모아 두고, 요청 처리(`Process*`)가 성공한 끝에서 `TakeItemChanges`로 꺼내 응답에 싣는다. 착용과 해제는
한 컨테이너를 바꾼 뒤 다른 컨테이너를 바꾸는데, 두 번째 단계가 실패하면 `nullopt`를 돌려주면서 첫 단계의 바뀐 칸을 꺼내지
않는다. 그 칸은 다음 아이템 요청의 응답에 함께 실린다. 지금은 앞선 검사가 두 번째 단계의 실패를 막으므로 실행되지 않는 경로다. 첫 단계의 변경을
되돌리지 않는 문제는 칸 배열로 옮기기 전에도 있었다. 코드를 읽고 판단했다.

### 영향

**버그 발생 가능성 증가** — 앞선 검사와 두 번째 단계의 조건이 어긋나는 변경이 들어오면, 아이템이 사라지고 클라이언트의 칸이 서버와 어긋난다.

## TD-075 클라이언트 빌드 스크립트가 다른 워크트리의 에디터를 이 프로젝트의 에디터로 본다
> **심각도:** 낮음 · **난이도:** 낮음 · **범위:** 함수 · client
> 위치: `P1/Scripts/Invoke-UeBuild.ps1` 123~127줄
> 등록일: 2026년 10월 23일

스크립트는 떠 있는 에디터의 명령줄에 프로젝트 파일 이름(`P1.uproject`)이 들어 있는지만 본다. 워크트리마다 프로젝트 파일 이름이
같다. 그래서 다른 워크트리에서 연 에디터가 떠 있으면 이 워크트리의 빌드도 「이 프로젝트를 연 에디터가 떠 있다」며 1로 끝난다.

## TD-081 새 워크트리에서 띄운 에디터는 언리얼 MCP 서버를 열지 않는다
> **심각도:** 낮음 · **난이도:** 낮음 · **범위:** 파일 · client

언리얼 MCP 서버를 에디터가 띄울 때 여는 설정(`bAutoStartServer=True`, 포트 8000)은 git이 추적하지 않는 사용자별 설정 파일에만 있다.

### 영향

**작업 흐름 정지** — 워크트리 세션이 언리얼 MCP로 에디터 작업을 하려면 사람이 설정을 옮기거나 에디터에서 서버를 켜야 한다.

## TD-084 귀환하며 회복한 몬스터의 HP를 클라이언트가 모른다
> **심각도:** 낮음 · **난이도:** 중간 · **범위:** 기능 · server, client, protocol
> 위치: `Server/GameServer/Game/AI/MonsterAIComponent.cpp` `MonsterAIComponent::RecoverHp`
> 등록일: 2026년 10월 29일

귀환하는 몬스터는 서버에서 HP를 회복하지만 서버가 그 값을 보내지 않는다. 몬스터의 HP를 실어 보내는 패킷은 피격(`S_HIT`)과 스폰(`S_SPAWN`)뿐이다.
그래서 이미 그 몬스터를 보던 클라이언트의 HP 표시는 다음 피격이나 다시 보일 때까지 회복 전 값에 머문다. 다음 피격의 HP는 서버 값이라 그때 한 번에 오른다.
#340에서 귀환 중 회복을 만들 때 프로토콜에 HP 갱신 통지를 더하지 않았다. PIE로 확인하지 않았다.

### 영향

**표시 어긋남** — 끌고 가다 놓친 몬스터를 다시 때리면 HP 바가 갑자기 차오른다. 판정은 서버 값으로 하므로 결과는 틀리지 않는다.
