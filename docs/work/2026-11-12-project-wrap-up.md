# 프로젝트를 마무리하고 README와 최종 문서 만들기

## 목표

- 공개 저장소의 README만 읽고 무엇을 만들었는지, 어떻게 띄우는지 알 수 있다
- 면접 전에 다시 읽을 최종 문서가 `docs/final/`에 있다
- 시연 영상의 대본이 `docs/final/`에 있다. 녹화는 이 작업에서 하지 않는다

## 결정

2026년 11월 12일에 사람과 정했다. 참고한 양식은 `Project_Dedicated` 저장소의 README와 그 PC의 `Docs/Final/`이다.

**티켓 구성** (같은 날 다시 정했다. 아래 결정과 다르면 이 문단이 우선한다)

- 남은 일을 티켓 셋으로 묶는다. #375는 기능 설명 문서, #376은 면접 준비 문서, #377은 README와 저장소 마무리다
- 사람은 이 작업에 손을 대지 않는다. 사람의 플레이 확인과 영상 녹화를 하지 않고, 하지 않았다는 것을 README에 밝힌다
- README에 영상 링크와 스크린샷을 넣지 않는다
- PR의 머지, `v1.0.0` 태그, `main` 갱신, 저장소 설명과 토픽은 에이전트가 한다. 훅이나 권한이 막으면 우회하지 않고 에러 원문을 남기고 멈춘다

**범위**

- 코드는 `dev`의 `6186a77f`에서 동결한다. 시연 경로를 막는 결함만 고치고, 나머지는 README 「알려진 한계」에 적는다
- 독자는 둘이다. README는 게임 서버 프로그래머 채용의 담당자와 면접관이 읽고, `docs/final/`은 면접을 준비하는 본인이 읽는다
- 공개하는 것은 README와 `docs/assets/`의 아키텍처 도해다. `docs/final/`은 추적하지 않는다
