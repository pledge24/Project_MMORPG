# 폴더 구조와 컨벤션 이행

이 문서는 이행의 계획과 결정을 담는다. 진행 상태는 담지 않는다. 상태는 `추적:`이 가리키는 맵 이슈와 그 자식 티켓에서 본다.

---

## 작업 배경

### 1. 지금 무엇이 안 되는가

1. **클라이언트 폴더가 도메인이 아니라 UE 타입으로 갈려 있다.** 기능 하나를 고치려면 서너 개 폴더를 오간다. `P1/Source/P1/P1.Build.cs`의 `PrivateIncludePaths`가 하위 폴더 12개를 전부 등록해 include를 평탄화하므로, 폴더를 옮겨도 빌드가 깨지지 않는 대신 경계 위반도 빌드가 잡지 않는다.

2. **리플렉션 타입 38개 중 34개에 프로젝트 약어가 없다.** 엔진과 플러그인의 클래스 이름과 충돌할 자리가 열려 있다. 나중에 고치면 그 클래스를 부모로 삼은 블루프린트가 부모를 잃는다.

3. **`P1/Content/`의 에셋 3,438개 중 47개만 git에 있다.** `P1/Config/DefaultEngine.ini`의 `GameDefaultMap`이 가리키는 `Content/Maps/LoginMap.umap`이 추적되지 않는다. 새로 클론하면 게임이 시작할 맵이 없다.

4. **계약 원본이 한쪽 티어 안에 있다.** `.proto` 3개가 `Server/Common/Protobuf/bin/`에서 `protoc.exe`, `PacketHandlerGenerator.exe`와 같은 폴더에 산다. 두 티어가 공유하는 유일한 계약인데 서버 소유처럼 보이고, 폴더 이름 `bin`이 원본을 빌드 산출물로 오해하게 만든다.

5. **서버의 멤버 변수 이름 규칙이 갈려 있다.** `ServerCore`는 `_camelCase`로 통일했고(57 대 3) `GameServer`는 접두사 없는 쪽이 다수다(32 대 78). `Game/Object/Player.h`와 `Game/Object/Monster.h`는 한 클래스 안에서 두 규칙이 섞인다.

6. **로그 카테고리를 선언해 두고 쓰지 않는다.** `P1/Source/P1/Log/LogCategory.h`가 6종을 선언하는데, 실제 호출은 `LogTemp`가 36회이고 선언한 카테고리는 8회다.

### 2. 원하는 결과

1. 규범이 저장소 안의 두 문서에 있다. 그 두 문서만 읽으면 새 파일을 어디에 어떤 이름으로 만들지 정해진다.
2. 규범 위반을 사람이 아니라 CI가 잡는다.
3. 이행이 여러 세션에 걸쳐도 진행 상태와 다음 할 일이 한 번의 조회로 읽힌다.

### 4. 반드시 지킬 것

- 검증 명령을 실제로 실행한 결과 없이 완료를 선언하지 않는다. (`CLAUDE.md` 「완료 기준」)
- 에셋과 폴더의 이동과 이름 변경은 언리얼 에디터 안에서만 한다.
- 계획 밖에서 발견한 부채는 즉석에서 고치지 않는다. `docs/tech-debt.md`에 적고 넘어간다.
- `.proto`와 `.bat`의 cp949 인코딩을 UTF-8로 바꾸지 않는다.
- 생성물을 손으로 고치지 않는다. 손으로 쓰는 것은 `ServerPacketHandler.cpp`와 `ClientPacketHandler.cpp` 둘뿐이다.
- `.claude/hooks/guard_dangerous_cmd.py`를 에이전트가 편집하지 않는다.
- ADR은 자기 완결적으로 쓴다. 임시 자료를 링크하지도 언급하지도 않는다.
- 커밋 메시지는 `git commit -F <파일>`로 넣는다.

### 5. 미결정 사항

1. **`P1/Source/P1/Network/`의 `.proto` 사본 3개를 UE 빌드가 쓰는지.** 참조용 사본으로 보이지만 확인하지 않았다.
2. **`Sync/`와 `Entities/`에 넣을 코드의 경계.** `Game/Objects/Creature.h`의 이동 보간 로직은 클래스를 나눈 뒤에야 옮길 수 있다. 이번 이행에서는 폴더만 만들고 코드 분리는 하지 않는다.

#### 판정이 끝난 것

2026년 9월 19일에 언리얼 MCP의 `AssetTools.get_dependencies`와 `get_referencers`로 확인했다.

**`Content/LevelPrototyping/`의 13개는 닫힌 섬이다. 삭제한다.**

- `InGameMap`과 `LoginMap`의 의존 목록에 `/Game/LevelPrototyping/`이 없다. `InGameMap`이 쓰는 그리드 머티리얼은 엔진 쪽 `/Engine/OpenWorldTemplate/LandscapeMaterial/MI_ProcGrid`다.
- 메시 5개(`SM_Cube`·`SM_ChamferCube`·`SM_Cylinder`·`SM_QuarterCylinder`·`SM_Ramp`)의 역참조가 0건이다.
- 나머지 8개는 서로만 참조한다. 폴더 밖에서 이 13개를 참조하는 에셋이 없다.

**`Content/__ExternalActors__/ThirdPerson/`의 1개는 고아다. 삭제한다.**

- `/Game/ThirdPerson/Maps/ThirdPersonMap`이 존재하지 않는다.
- `/Game/ThirdPerson` 폴더 자체가 없다.
- 외부 액터 파일도 에셋으로 등록되어 있지 않다. 에디터가 보지 못하는 디스크상의 잔재다.

**`Content/Assets/Icon/`의 40개가 22MB인 원인은 임포트 후처리 부재다.**

- 만든 아이콘을 에디터에 그대로 넣고 텍스처 그룹과 밉맵과 압축을 조정하지 않았다.
- 원인을 확인했으므로 미결정에서 내린다. 설정은 표 G7대로 이번 이행에서 조정한다.

**아이콘 40개의 설정을 조정하고 실측했다 (2026년 9월 20일).**

- 40개 전부가 `TEXTUREGROUP_UI`이고 `TMGS_NoMipmaps`이며 `TC_EditorIcon`이다. 표본이 아니라 한 장씩 개별로 읽어 확인했다.
- 폴더 용량이 22,704,655바이트에서 21,905,734바이트로 3.52% 줄었다.
- **줄어드는 폭이 작은 것은 `.uasset` 용량의 대부분을 임포트 소스 아트가 차지하기 때문이다.** 밉맵 제거가 지우는 것은 그 바깥의 파생 데이터뿐이다. 더 줄이려면 원본 이미지의 해상도를 낮춰 다시 임포트한다.
- **디스크 용량과 런타임 텍스처 메모리는 반대로 움직인다.** `TC_Default`는 블록 압축이라 픽셀당 1바이트 안쪽을 쓰고, `TC_EditorIcon`은 무압축 RGBA8이라 4바이트를 쓴다. 밉맵을 꺼서 33%를 돌려받아도 압축을 푼 손실이 더 크다. UI 텍스처의 표준 선택이므로 규범은 그대로 두되, 두 수치가 같이 줄지 않는다는 것은 기록해 둔다.
- 압축 설정 `UserInterface2D`는 UE 5.8의 드롭다운에서 `Uncompressed(RGBA8)`로 표시된다. 내부 값은 `TC_EditorIcon`으로 같다.

### 되돌리기 어려운 결정

#### 저장소 최상위를 부분만 재배치한다

**채택**: `P1/`을 그대로 두고 `Protocol/`, `DesignData/`, `Tools/`를 최상위에 만든다.
**기각**: `P1/`을 `Client/`로 옮기는 안. `Shared/`를 만드는 안.
**근거**: 저장소에 언리얼 클라이언트가 하나뿐이라 `P1/`이 곧 클라이언트다. 이름을 바꿔 얻는 것은 가독성 하나인데, 그 변경이 CI 워크플로, 훅, 테스트 스크립트, 문서의 경로 참조를 전부 건드린다. 검증 수단에 파급이 몰린다. 반대로 `Protocol/`은 두 티어가 공유하는 유일한 계약이므로 양쪽 바깥으로 꺼내면 소유권이 구조로 드러난다. `Shared/`는 대상 코드가 0줄이다.
**틀렸다는 신호**: 언리얼 클라이언트가 둘 이상이 되거나, `P1`이라는 이름이 프로젝트 이름과 어긋나기 시작한다. 또는 언리얼 타입에 의존하지 않는 공용 C++가 200줄을 넘는다.
**승격**: ADR-0004

#### include 평탄화를 제거한다

**채택**: `PrivateIncludePaths`에서 도메인 폴더를 뺀다. `#include "Combat/AttackSystemComponent.h"`처럼 경로를 한정한다.
**기각**: 평탄화를 유지한 채 폴더만 도메인으로 바꾸는 안.
**근거**: 평탄화를 유지하면 폴더 이름만 바뀌고 문제는 남는다. `docs/ARCHITECTURE.md`가 "리뷰가 유일한 방어선이다"라고 적은 상태가 그대로다. 평탄화를 없애면 `#include` 줄에 도메인 이름이 드러나서 경계 위반이 검색 한 번으로 잡힌다. 컴파일러가 막아 주지는 않는다. 그것은 모듈을 나눠야 가능하고 지금 규모에서는 모듈을 나누지 않는다.
**틀렸다는 신호**: 경로 한정 include를 도입했는데도 도메인을 넘는 include가 계속 늘어난다. 그러면 모듈 분리를 검토할 시점이다.
**승격**: ADR-0005

#### Content를 부분만 버전 관리한다

**채택**: 자작 에셋 123개(47MB)를 Git LFS로 추적한다. 외부 팩 3,300여 개는 추적하지 않는다.
**기각**: Content 전체를 추적하는 안. 지금처럼 47개만 추적하는 안.
**근거**: 자작 에셋은 잃으면 다시 만들어야 한다. 외부 팩은 Fab에서 설치하면 같은 경로에 같은 에셋이 그대로 들어온다. 추적 여부를 가르는 기준은 용량이 아니라 복구 가능성이다. 지금 `GameDefaultMap`이 가리키는 맵조차 추적되지 않아 새로 클론하면 게임이 시작할 맵이 없다.
**틀렸다는 신호**: 외부 팩을 직접 편집하기 시작한다. 편집한 팩은 설치로 복구되지 않으므로 그 시점에 `Content/External/`로 옮기고 추적 대상에 넣는다.
**승격**: ADR-0006

#### 서버 빌드를 MSBuild로 유지한다

**채택**: MSBuild와 `ServerCore` + `GameServer` 2프로젝트 구조를 유지한다. 폴더의 분류명만 조정한다.
**기각**: CMake로 전환하고 `Server/src/` 단일 트리로 합치는 안.
**근거**: `ServerCore`는 재사용 가능한 IOCP·잡큐·DB 코어이고 `GameServer`는 게임 규칙이다. 이 분리는 단일 트리보다 경계가 분명하다. 빌드 도구를 바꿔도 CI가 호스티드 러너에서 서버를 빌드하지 못하는 제약은 그대로다. 그 제약의 원인은 빌드 도구가 아니라 `PlatformToolset` v145다.
**틀렸다는 신호**: 서버를 Windows 밖에서 빌드해야 하는 요구가 생긴다.
**승격**: 없음. `docs/adr/0001-unify-build-path.md`에 한 문단을 덧붙인다.

## 위험 요소

1. **단계 7이 가장 위험하다.** protobuf 생성물은 `#include "Enum.pb.h"` 형태로 서로를 부르고, 생성물은 손으로 고칠 수 없다. `PrivateIncludePaths`를 통째로 비우면 이 include가 깨진다. 생성물이 있는 폴더는 include 경로에 남긴다.

2. **단계 8은 결과를 에디터 밖에서 알 수 없다.** C++ 빌드가 통과해도 블루프린트가 부모를 잃었는지는 에디터를 열어야 안다. 더 나쁜 경우는 `[CoreRedirects]` 항목을 쓰기 전에 에디터가 블루프린트를 로드해서 부모를 날리는 것이다. **리다이렉트 항목을 먼저 쓰고 빌드한 뒤에 에디터를 연다.**

3. **`git lfs migrate`를 쓰지 않는다.** 이력을 다시 쓰면 커밋 해시가 바뀐다. 이미 추적 중인 47개는 일반 blob으로 두고 앞으로의 커밋만 LFS로 보낸다. 같은 확장자의 파일이 두 형태로 섞이지만 동작한다.

4. **`.bat` 파일의 경로를 고칠 때 인코딩이 깨질 수 있다.** `GenPackets.bat`과 `GenJsonFile.bat`은 cp949다. 셸을 거치지 않는 편집 도구를 쓰고, 고친 뒤 실행해서 한국어 출력이 깨지지 않는지 본다.

5. **Fix Up Redirectors가 미추적 외부 팩을 건드릴 수 있다.** 단계 11에서 실행할 때 대상 폴더를 `Content/P1/`로 제한한다.

6. **단계 2 이전에는 에디터 작업의 결과를 되돌릴 수 없다.** 그래서 Content를 git에 들이는 것이 에디터를 쓰는 모든 단계보다 앞에 온다.

### 순서의 근거

이 절은 티켓에 없다. 티켓은 "무엇을 하는가"를 담고, 여기는 "왜 이 자리인가"를 담는다.

**1번이 맨 앞인 이유**: 규범이 있어야 나머지 단계가 무엇을 목표로 하는지 정해진다. 규범 없이
폴더를 옮기면 옮긴 자리가 맞는지 판정할 근거가 없다.

**2번과 3번이 앞인 이유**: 죽은 파일을 옮기고 이름 바꾸는 것은 낭비다. 먼저 치우면 뒤따르는 모든
단계의 대상 수가 줄어든다.

**3번이 4번보다 앞인 이유**: 4번에서 Content가 LFS로 들어간다. 그 뒤에 아이콘을 고치면 부풀어
있는 원본과 줄어든 버전이 둘 다 이력에 남는다.

**4번이 에디터를 쓰는 세 단계(10, 13, 14)보다 앞인 이유**: 그 전까지는 에디터에서 무엇을 하든
되돌릴 수 없다. 에셋 이동은 에디터 안에서만 할 수 있는데 그 결과가 git에 남지 않는다.

**5번이 8번보다 앞인 이유**: 둘 다 `GenPackets.bat`의 목적지 경로를 고친다. 같은 파일을 두
브랜치에서 고치면 충돌한다.

**8번 다음에 9번인 이유**: 폴더를 먼저 옮기고 평탄화를 나중에 없앤다. 반대로 하면 `#include`를
옛 구조 기준으로 한 번, 새 구조 기준으로 또 한 번, 두 번 고치게 된다.

**10번이 4번 뒤인 이유**: 리네임이 블루프린트를 건드린다. Content가 추적되기 전이면 그 변경이
diff에 남지 않는다.

**12번이 10번과 11번 뒤인 이유**: 멤버 재정렬은 초기화 순서를 바꿀 수 있어 이 이행에서 가장
위험한 축이다. 다른 변경이 끝난 뒤에 두어야 회귀가 났을 때 원인이 하나로 좁혀진다.

**14번이 13번 뒤인 이유**: 둘 다 WBP를 건드린다.

**15번이 마지막 직전인 이유**: 검사 스크립트는 모든 규칙이 실제로 적용된 뒤에 켠다. 먼저 켜면
CI가 계속 빨갛고, 빨간 CI는 곧 아무도 보지 않는 CI가 된다.

## 작업 루프

이 절은 다음 세션이 맥락 없이 시작해도 작업을 이어가기 위한 절차다.

### 역할 분담

| 무엇 | 어디 |
| --- | --- |
| 계획과 결정, 단계와 증명 | 이 문서 |
| 규범 | `docs/conventions.md`, `docs/folder-structure.md` |
| 되돌리기 어려운 결정의 근거 | `docs/adr/` |
| 진행 상태 | GitHub Issues |
| 세션별 기록 | `session-report` 산출물 |

같은 상태를 두 곳에 적지 않는다. 진행 상태는 GitHub Issues에만 있다.

### 티켓 발행 (2026년 9월 19일에 끝남)

맵 이슈 #38과 자식 티켓 16개(#39~#54)를 발행했다. 차단 관계 22개를 GitHub의 issue dependencies로
걸었고, 자식 연결 16개를 sub-issues로 걸었다. 각 티켓 본문이 그 단계의 할 일과 완료 조건을 갖는다.

다시 할 일은 없다. 아래 「매 세션」부터 읽는다.

### 매 세션

1. **읽는다**: `CLAUDE.md`, `docs/conventions.md`, `docs/folder-structure.md`, 그리고 집을 티켓 하나.
2. **집는다**: 열린 티켓 중 차단이 없는 첫 번째를 `gh issue edit <n> --add-assignee @me`로 claim한다. 이것이 세션의 첫 쓰기다.
3. **판다**: `<카테고리>/<이슈번호>-<요약>` 형식으로 브랜치를 만든다.
4. **만든다**: `implement` 스킬로 그 티켓만 처리한다. 계획 밖에서 발견한 부채는 `docs/tech-debt.md`에 적고 넘어간다.
5. **검증한다**: 티켓의 「증명」에 적힌 명령을 실제로 실행한다. 종료 코드를 티켓에 적는다.
6. **올린다**: `gh pr create --body-file <파일>`로 PR을 만든다. 「검증」에는 직접 실행해 확인한 것만 적는다.
7. **닫는다**: PR이 머지되면 티켓을 닫는다.
8. **남긴다**: `session-report` 스킬로 기록을 만든다.

### 막혔을 때

우회하지 않는다. 무엇이 어디서 막혔는지 에러 원문과 `file:line`으로 티켓에 적고 멈춘다. 에디터나 사람 손이 필요한 작업은 우회로를 찾지 않고 기록한 뒤 넘긴다.

### 몇 단계마다

`code-review-matt` 스킬의 Standards 축으로 규범 준수를 판정한다. 이 스킬은 저장소에 문서화된 코딩 표준을 읽으므로, 단계 0이 끝나면 별도 설정 없이 작동한다.

### 세션이 끊겼을 때

프론트매터 `추적:`의 맵 이슈를 연다. 열린 자식 티켓 중 차단이 없는 첫 번째가 다음 할 일이다. 이 문서의 「단계와 증명」에서 같은 번호의 단계를 찾아 맥락을 복원한다.

## 참고

이 절은 작업이 끝나면 통째로 삭제한다.

- 이행의 입력이 된 참고 문서 2개는 `docs/references/newConvention/`에 있다. 추적하되 어떤 성격의 자료인지를 커밋 메시지에 남긴다. 단계 13에서 폴더를 지우고 삭제 이유도 커밋 메시지에 남긴다.
- 참고 문서는 새 프로젝트 시작을 전제로 쓰여 있고, A안(언리얼 데디케이티드 서버)과 GAS 사용 분기를 함께 담고 있다. 이 프로젝트는 외부 C++ 서버를 쓰고 GAS를 쓰지 않으므로 두 분기의 서술 중 절반은 이 저장소에 적용되지 않는다.
- **규범 문서와 ADR은 이 자료를 언급하지 않는다.** 이력에 남아 있더라도 마찬가지다. 자기 완결적으로 쓴다.
