# DB 인스턴스는 티어마다 하나를 두고, 인스턴스 이름은 티어를 따른다

LocalDB 인스턴스는 그 인스턴스를 소유한 티어마다 하나씩 둔다. 인스턴스 이름은 `P1` 접두사에 티어 이름을 붙이고(`P1Auth`),
그 안의 데이터베이스 이름은 데이터 영역을 따른다(`AccountDB`). 한 티어가 데이터 영역을 더 맡게 되면 같은 인스턴스에
데이터베이스를 더한다. 2026년 10월 19일 인증 서버 재구성(#231)에서 정했다.

## 인스턴스를 티어 단위로 나누는 이유

LocalDB 인스턴스는 SQL Server 프로세스 하나이고, 운영 환경의 DB 서버 한 대에 해당한다. 운영 환경에서 DB 서버를 나누는
단위는 그 DB를 소유한 서비스다. 개발 머신에서도 같은 단위로 나누면 「각 DB는 소유 티어만 접근한다」는 불변식을 접속
권한이 아니라 접속 대상 자체로 지킨다. 게임 서버의 접속 문자열은 인증 티어의 인스턴스를 가리키지 않는다.

데이터 영역은 데이터베이스로 나눈다. 예를 들어 결제가 생기면 결제를 소유한 티어에 따라 자리가 정해진다.

- 인증 서버가 결제를 맡으면 `P1Auth`에 `BillingDB`를 더한다
- 결제를 별도 티어로 두면 그 티어의 인스턴스(`P1Billing`)를 새로 만든다

## 검토한 대안

- **인스턴스 하나(`P1`)에 모든 데이터베이스를 둔다.** 개발 환경은 가장 단순하다. 하지만 티어 사이의 경계를
  로그인 권한으로만 지키게 되고, 권한 설정을 빠뜨리면 다른 티어의 DB를 읽는 코드가 조용히 동작한다.
- **데이터베이스마다 인스턴스를 둔다(`P1Account`).** 데이터 영역이 늘 때마다 인스턴스가 함께 는다. 한 티어가
  여러 데이터베이스를 한 트랜잭션으로 묶을 수 없게 된다.
- **기본 인스턴스 `MSSQLLocalDB`를 계속 쓴다.** SQL Server와 Visual Studio가 자동으로 만들고 다른 도구도 함께 쓰는
  인스턴스라서, 이 프로젝트의 DB가 다른 도구의 DB와 섞인다.
