# 공간 정보는 에디터 전용 마커로 레벨에 배치하고 추출한다

서버가 알아야 하는 공간 정보(스폰 지점, 리스폰 지점, 지역의 경계, NPC의 위치, 맵 경계)는 레벨에 마커 액터로 배치한다. 마커는
에디터 전용 액터라 쿠킹에서 빠진다. 커맨드렛이 레벨의 마커를 읽어 서버가 읽는 배치 데이터를 쓰고, 그때 정합성을 검사한다.
마커에는 공간과 기획 데이터의 행 번호만 두고, 규칙과 수치는 기획 데이터에 둔다. 2026년 10월 29일 맵 데이터 추출 작업의
설계에서 정했다.

## 이전 방식과 문제

지역의 중심과 반경, 리스폰 좌표, 포털 좌표를 엑셀에 숫자로 적었다. 이 방식에서는 기획이 배치 결과를 볼 수 없다. 레벨에 놓인
것(포털 액터, 경계 벽)과 표의 숫자를 사람이 손으로 맞춰야 했고, 경계 벽의 크기는 주석으로 「서버 값과 맞춘다」고 적어 둘
뿐이었다.

## 결정

- 마커는 런타임 모듈의 베이스 클래스를 상속하고, 베이스가 에디터 전용 액터로 표시한다. 마커는 PIE에는 있지만 쿠킹한 빌드에는 없다
- 클라이언트에도 보여야 하는 배치물은 마커가 아니다. 포털은 레벨에 남는 액터의 포털 번호를 추출한다. NPC는 서버 엔티티라서
  마커가 위치와 NPC 번호만 갖고, 서버가 만들어 클라이언트에 알린다
- 「공간은 에디터, 규칙은 표, 연결은 번호」다. 스폰 마커는 위치, 반경, 스폰 그룹 번호만 갖고, 몬스터 종류와 최대 수와 리젠 시간은
  스폰 그룹 표에 있다
- 추출은 커맨드렛이 한다. 에디터를 띄우지 않고 스크립트 하나로 돌고, 문제가 있으면 0이 아닌 코드로 끝난다
- 산출물은 DataBuilder의 산출물과 다른 폴더에 쓰고 git에 커밋한다. 한 행 한 줄로 정렬해 배치를 바꾼 결과가 diff로 드러난다

## 검토한 대안

- **엑셀에 좌표를 적는다(이전 방식).** 위의 문제가 남는다.
- **마커의 속성에 규칙과 수치까지 둔다.** 배치 작업자가 한 자리에서 다 보지만, 몬스터 수나 리젠 시간을 밸런싱하려면 레벨을
  열어야 하고, 수치가 엑셀과 레벨 두 곳에 나뉜다.
- **서버가 레벨 파일을 직접 읽는다.** UE 에셋 형식을 서버가 해석해야 한다.
- **별도 맵 툴을 만든다.** 레벨 에디터와 같은 기능을 다시 만드는 일이다.

## 결과

- 지역 표와 포털 표에서 좌표 열이 사라진다. 지역 표에는 지역 고유의 규칙만 남는다
- 레벨을 고친 사람이 추출을 다시 돌리지 않으면 서버가 옛 배치를 쓴다. 추출이 낡았음을 감지하는 일은 백로그에 있다
