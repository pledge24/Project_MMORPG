# 에셋 참조를 기획 원본에 두지 않는다

기획 원본(`DesignData/*.xlsx` → `C_*.json` → `DT_Item` 같은 수치 테이블)은 수치만 담는다. 아이콘,
메시, 몬스터 클래스 같은 에셋 참조는 에디터가 소유하는 에셋 테이블(`DT_ItemAssets`,
`DT_MonsterAssets`)에 두고, 이 테이블은 JSON에서 임포트하지 않는다. 두 테이블은 행 이름
`TemplateId`로 짝을 맺는다.

아이템 하나의 정보가 테이블 두 개에 나뉘어 있어서 하나로 합치고 싶어진다. 합치지 않는 이유를 적는다.

## 문자열 경로는 에셋을 옮길 때마다 낡는다

에디터는 에셋을 옮기면 그 에셋을 참조하는 `.uasset`을 새 경로로 다시 저장한다. 엑셀 셀과 JSON
안의 경로 문자열은 에디터가 모른다. 2026년 9월에 `Content/`를 재배치하자 `C_Item.json`의 경로
75건과 `C_Monster.json`의 경로 9건이 모두 없는 자리를 가리키게 됐다. `DT_Item`은 에디터가 고쳐
두어서 멀쩡했지만, 엑셀을 고쳐 JSON을 다시 만들고 재임포트하면 옛 경로로 되돌아가는 상태였다.

경로를 한 번 고쳐도 다음 이동에서 같은 일이 생긴다. 참조를 에디터가 관리하는 자리로 옮기는 것만이
이 반복을 끊는다.

## 검토한 대안

- **경로 대신 에셋 이름만 적고 런타임에 Asset Manager로 찾는다.** 폴더 이동에는 버티지만 이름을
  바꾸면 똑같이 낡는다. Asset Manager 설정도 새로 늘어난다.
- **구조는 두고 낡은 경로를 검사로 잡는다.** 낡는 즉시 알 수는 있지만 고치는 일은 계속 사람이 한다.
- **`DT_Item`을 원본으로 삼고 JSON 생성을 없앤다.** 서버가 같은 수치를 `S_Item.json`으로 읽으므로
  수치가 두 원본으로 갈라진다.

## 결과

- C++은 에셋 테이블을 쓰는 클래스의 `UPROPERTY`로 받고 블루프린트 기본값에서 지정한다. 경로를
  코드나 설정 파일에 문자열로 적지 않는다. `.ini`에 적는 방식도 에디터가 고쳐 주지 않는다.
- 새 아이템이나 몬스터를 추가하면 엑셀에 수치 행을, 에디터에서 에셋 테이블에 같은 `TemplateId`의
  행을 각각 넣는다.
