# 월드 선택이 인증 티켓을 발급하고, 게임 서버가 자기 월드를 Redis에 알린다

로그인과 게임 서버 접속 사이에 월드 선택을 넣는다. 로그인은 로그인 세션과 월드 목록을 돌려주고, 월드 선택이 그 월드에서만
쓸 수 있는 인증 티켓과 그 월드의 주소를 돌려준다. 월드 목록과 혼잡도는 게임 서버가 Redis에 주기적으로 쓰고, 인증 서버는 그
값을 그대로 전달한다. 2026년 10월 23일 로비 분리와 게임 입장 흐름 설계에서 정했다.

## 흐름

1. 로그인: 인증 서버가 계정을 확인하고 로그인 세션과 월드 목록을 돌려준다
2. 월드 선택: 인증 서버가 로그인 세션을 확인하고 정지 여부를 다시 본 뒤, 그 월드의 주소와 인증 티켓을 돌려준다
3. 로비 접속: 클라이언트가 그 주소로 연결하고 인증 티켓을 낸다

게임에서 월드 선택으로 돌아오면 클라이언트는 남아 있는 로그인 세션으로 월드 목록을 다시 받는다. 로그인 세션이 만료됐으면
로그인 화면으로 간다.

## HTTP API

| 요청 | 본문과 헤더 | 성공 응답 |
|---|---|---|
| `POST /api/auth/login` | `{ loginId, password }` | 200 `{ loginSession, worlds }` |
| `GET /api/worlds` | `Authorization: Bearer <로그인 세션>` | 200 `{ worlds }` |
| `POST /api/worlds/{worldId}/select` | 같은 헤더 | 200 `{ host, port, ticket }` |

- `worlds`의 각 항목: `{ worldId, name, congestion }`
- 늘어나는 실패: 로그인 세션이 없거나 만료됨(401 `LOGIN_SESSION_EXPIRED`), 월드 항목이 사라짐(409 `WORLD_UNAVAILABLE`),
  월드 선택에서 다시 확인한 정지(403 `ACCOUNT_BANNED`)

## Redis 계약

| 키 | 값 | TTL | 쓰는 쪽 → 읽는 쪽 |
|---|---|---|---|
| `loginSession:{값}` | 계정 번호 | 1시간 | 인증 서버 → 인증 서버 |
| `worlds` (집합) | 월드 번호 | 없음 | 게임 서버가 기동할 때 자기 번호를 넣음 → 인증 서버 |
| `world:{worldId}` | 이름, 주소, 혼잡도 | 15초. 게임 서버가 5초마다 갱신 | 게임 서버 → 인증 서버 |
| `authTicket:{worldId}:{티켓}` | 계정 번호 | 30초 | 인증 서버 → 그 월드의 게임 서버가 소비 |

- 로그인 세션의 수명은 로그인한 시각부터 고정이다. 월드 선택에 써도 지우지 않고, 다시 로그인해도 이전 로그인 세션을 지우지 않는다
- 인증 티켓의 키에 월드 번호가 들어간다. 한 월드에 발급한 티켓으로 다른 월드에 들어갈 수 없다
- `world:{worldId}`가 없는 월드는 목록에 나오지 않는다. 게임 서버가 꺼지면 15초 안에 목록에서 빠진다
- 혼잡도는 게임 서버가 자기 정원에 비춰 정한 단계다. 정원의 50% 미만이면 원활, 80% 미만이면 보통, 그 이상이면 혼잡이다.
  인증 서버와 클라이언트는 정원을 모르고, 혼잡도는 월드 선택을 막지 않는다

## 검토한 대안

- **로그인이 지금처럼 인증 티켓을 발급하고, 월드 선택은 주소만 돌려준다.** 바꿀 것이 가장 적다. 하지만 티켓의 30초가 월드
  선택 화면에서 흐르므로, 그 화면에 30초 넘게 머물면 티켓이 만료된다. TTL을 늘리면 탈취된 티켓이 유효한 시간도 함께 는다.
  또 월드 선택 요청에서 인증 서버가 계정을 확인할 수단이 티켓뿐이라, 티켓을 소비하지 않고 들여다보는 경로가 생긴다.
- **게임 서버가 꺼진 월드를 「점검」으로 목록에 남긴다.** 인증 서버가 월드가 있다는 사실을 따로 알아야 하므로 인증 서버
  설정에 월드 목록이 생긴다. 월드 목록의 원천이 둘이 된다.
- **혼잡도 대신 접속 계정 수와 정원을 그대로 보낸다.** 단계를 나누는 기준이 클라이언트로 간다. 정원은 게임 서버의 운영
  값이므로 인증 서버와 클라이언트가 알 이유가 없다.

## 결과

`docs/ARCHITECTURE.md`의 불변식 세 개가 바뀐다.

- 「인증 서버는 회원가입과 로그인 외의 일은 하지 않는다」에 월드 목록과 월드 선택이 더해진다
- 「두 티어를 잇는 선은 Redis의 인증 티켓 키 하나뿐이다」가 위 표의 네 키로 바뀐다
- 「인증 티켓을 발급하는 경로는 로그인 하나뿐이다」가 「월드 선택 하나뿐이다」로 바뀐다. 이 불변식의 근거였던 정지 검사는 월드
  선택이 다시 하므로 지켜진다. `LastLoginAt` 갱신은 로그인에 남는다

인증 서버에는 도메인 폴더 `world/`가 생긴다(ADR-0015).

## 틀렸다는 신호

- 혼잡한 월드의 입장을 막거나 대기열에 세워야 한다. 월드 선택이 정원을 알아야 하므로, 혼잡도를 단계로만 전달하는 결정을 다시 본다
- 월드 선택으로 돌아올 때마다 로그인 화면으로 간다는 불만이 나온다. 로그인 세션의 수명을 다시 본다
- 게임 서버 말고도 인증 티켓을 소비하는 티어가 생긴다
